- Tauri 2 desktop host
- Rust backend
- Native Windows controller input

Select a suitable audio/DSP architecture after inspecting available libraries, their documentation, and redistribution licenses.

Requirements:
- No VirtualDJ or loopMIDI dependency for standalone operation.
- One authoritative audio engine clock for both decks and sampler.
- Controller and mouse actions use the same command/state system.
- Playback, controller input, and recording continue when the UI is hidden.

- Publish engine state to the UI at an appropriate bounded rate.

AUDIO AND TRANSPORT

Implement real:
- Independent two-deck playback
- WAV and MP3 import/playback initially
- Additional formats only when tested
- Accurate seek, pause, resume, end-of-track handling
- Independent deck volume and gain
- Crossfader with selectable curve
- Filter sweep
- Master meters and clipping indication
- Configurable output device and supported buffer settings

Loading a track must not interrupt the other deck.

A playing deck must not be overwritten without explicit confirmation. The default preparation deck is a nonplaying deck. If both are playing, require an explicit deck choice and confirmation.

CUE AND HOT CUES

Cue is separate from play/pause.

Define and document conventional cue behavior:
- Set cue while paused
- Return to cue
- Hold to preview where applicable
- Release to return unless playback was explicitly committed

Provide at least eight hot cue slots per deck:
- Set, trigger, and clear
- Persistent per-track positions
- Visible labels/colors
- Confirmation or modified gesture for destructive clearing

WAVEFORMS, BPM, AND SYNC

- Analyze actual audio samples for waveform data.
- Render aligned waveforms using engine playback position.
- Provide beat and bar markers derived from the beat grid.
- Support waveform zoom and overview seeking.
- Detect BPM asynchronously, with manual BPM and beat-grid correction.
- Distinguish detected, manually corrected, and unknown values.
- Provide tap tempo.
- Implement tempo matching and phase alignment with clearly defined master/follower behavior.
- Label tempo-only matching honestly if phase synchronization is not yet implemented.
- Do not show invented BPM, key, beat grids, or waveform data in real tracks.

EFFECTS

Implement audible DSP for:
- Backspin
- Brake stop
- Brake start
- Echo/echo out
- Reverb
- Filter

Expose relevant duration, wet/dry, and parameter controls.

Backspin must produce reversed/slowing audio behavior.
Brake stop must decelerate playback.
Brake start must accelerate into playback.

Lock the selected effect target for the duration of an active effect. Changing target deck must not transfer an executing effect abruptly.

STEMS

Provide:
- Vocal isolation
- Instrumental isolation
- Vocal mute
- Restore full mix
- Drums, bass, music, and vocals where supported by the selected model

Use a real, legally redistributable separation engine/model.
Document model download size, license, hardware requirements, and CPU/GPU support.

Prefer asynchronous precomputation and caching when real-time separation is unsuitable.

Maintain sample alignment between stems.
Vocal and instrumental isolation must be mutually exclusive.
If stems are unavailable or processing, explain that state and disable dependent actions.

Never simulate stem separation with an ordinary EQ and label it stems.
